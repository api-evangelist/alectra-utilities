# Alectra Utilities

> Ontario's second-largest municipally owned electricity distributor, serving roughly
> one million customers across seventeen communities in the Greater Toronto and
> Hamilton Area and the Golden Horseshoe. Its only API surface is Green Button Connect
> My Data, which exists because Ontario Regulation 633/21 (Energy Data) requires every
> Ontario electric and gas utility to implement Green Button Download My Data and
> Connect My Data to the NAESB REQ.21 ESPI v3.3 standard. There is no developer
> portal, no published base URI, no first-party OpenAPI and no self-serve access.

Generated by the API Evangelist enrichment pipeline on 2026-07-27 from apis.yml and
the artifacts in this repository. Alectra publishes no llms.txt (probed 2026-07-27:
alectrautilities.com/llms.txt HTTP 404, both Savage Data hosts HTTP 404).

## What an agent needs to know first

- The Connect My Data API is **not callable without approval**. A third party must
  register at the onboarding site, accept the Green Button Connect My Data Terms and
  Conditions of Access and Use, be approved by Alectra, and then be authorised by an
  individual customer. Only then is a base URI and OAuth client issued.
- **No base URI is published.** Do not infer one. Every path on Alectra's Green Button
  portal host HTTP 302 redirects to a customer sign-in, including deliberately
  invented control paths, so a response from that host proves nothing.
- The data is **personal consumption data for an identified retail customer**, usable
  only for the purpose that customer consented to.
- **Alectra has no open data.** No outage feed, no load or DER dataset, no capacity
  API. In Ontario the market and system data layer belongs to the IESO and the Ontario
  Energy Board, not to the distributor.

## APIs

- [Green Button Connect My Data (CMD)](https://alectrautilities.com/green-button-connect-my-data-terms-and-conditions-access-and-use): mandated consumer energy-data API to NAESB REQ.21 ESPI; consent-gated and approval-gated; no published base URI.

## Specs

- [Green Button ESPI OpenAPI](openapi/alectra-utilities-green-button-espi-openapi.json): OpenAPI 3.0.0, 7 GET operations. **Authored by the Green Button Alliance, not by Alectra** — harvested verbatim as the contract the mandate obliges Alectra to conform to. Its servers[] entry is the GBA public sandbox, not an Alectra host.

## Artifacts in this repository

- [Authentication](authentication/alectra-utilities-authentication.yml): OAuth 2.0, authorizationCode + clientCredentials; onboarding gate.
- [OAuth scopes](scopes/alectra-utilities-scopes.yml): none published; scope is issued at consent time.
- [Conventions](conventions/alectra-utilities-conventions.yml): Atom + ESPI XML, offset paging, RFC 3339 filters, depth expansion, no idempotency contract, no rate-limit signalling.
- [Error catalog](errors/alectra-utilities-problem-types.yml): bare 400 / 403; no RFC 9457.
- [Data model](data-model/alectra-utilities-data-model.yml): ApplicationInformation, Authorization, UsagePoint, Batch/Bulk over an Atom envelope.
- [Conformance](conformance/alectra-utilities-conformance.yml): what the contract does and does not conform to, with evidence.
- [Lifecycle](lifecycle/alectra-utilities-lifecycle.yml): versioning, the mandate timeline, and the absence of a status page, SLA or changelog.
- [Well-known](well-known/alectra-utilities-well-known.yml): nothing published; includes the control probes proving the 200s and 302s are catch-alls.
- [Domain security](security/alectra-utilities-domain-security.yml): TLS, HSTS, DNSSEC, CAA, SPF and DMARC for Alectra's domain and the vendor domain that actually hosts the data surface.
- [MCP (candidate)](mcp/alectra-utilities-mcp.yml): no server exists; a derived candidate tool list.
- [Agent skills](skills/_index.yml): three operating skills grounded in real ESPI operation ids.
- [Packages](packages/alectra-utilities-packages.yml): no first-party SDK; Green Button ecosystem libraries only.
- [Review](review.yml): the full 2026-07-27 verification record, including every probe and its HTTP status.
